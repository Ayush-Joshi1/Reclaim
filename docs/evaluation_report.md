# Reclaim Evaluation Proof

## 1. Evaluation Overview

This evaluation uses the repository’s current deterministic evaluation framework in `backend/app/evaluation/run.py`. It generates a synthetic dataset of failed-payment scenarios, runs the actual Reclaim risk engine and decision logic, and calculates business and agent metrics from the resulting outcomes.

This is not a live production benchmark and it does not evaluate real Razorpay or a live LLM provider. The current evaluation is intentionally synthetic and deterministic.

## 6. Scenarios Covered by the Evaluation

The current generator in `backend/app/evaluation/run.py` creates synthetic records for the following scenario types:

- `high_recovery_likelihood`
- `medium_recovery_likelihood`
- `low_recovery_likelihood`
- `high_value_requires_approval`
- `repeated_failure_stop`
- `strong_success_history`
- `repeated_customer_failures`
- `previous_recovery_attempts`
- `recent_failure`
- `expired_recovery_window`

These scenarios are used to exercise deterministic risk scoring, eligibility gating, approval thresholds, and stop conditions.

## 8. What This Evaluation Proves

This evaluation proves that the current repository contains a working deterministic evaluation pipeline for the Reclaim decision flow using the actual project code:

- the synthetic dataset is generated reproducibly
- the actual risk engine is applied to each record
- the actual recovery decision service is used
- deterministic validation and safety logic is evaluated
- business and agent metrics are calculated from the evaluated records
- the project test suite passes in the current repository state

This is real repository-level proof for the implemented logic.

## 9. What This Evaluation Does NOT Prove

This evaluation does not prove:

- live production performance
- live business recovery success with real payments
- live Razorpay provider execution success
- live LLM quality from a real LLM provider
- real-world deployment health or cloud uptime

The current evaluation uses `FakeLLMClient` from `backend/app/services/llm_client.py`, not a live LLM. The evaluation path also does not invoke real Razorpay provider calls; it evaluates internal logic and deterministic data, not live external provider execution.

## Final Note

The current project is therefore proven to have a working deterministic evaluation framework and passing repository tests, but not a live external deployment proof.
